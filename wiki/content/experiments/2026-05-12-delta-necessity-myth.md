# Experiment: 提莫鬼索 Δ = 0.00 的真相 —— Δ 的两种常见误读，与「必要性」的引入
**Status**: 🧪 draft
**Date**: 2026-05-12
**Module**: 2

> **数据范围**：本文所有数据均为 **diamond+ rank、过去 7 天**，覆盖 challenger / GM / master / diamond 四档。
> **AVP / w/ / w/o**：来自 MetaTFT API 的原始 `placement_count`（在数据网站同样 filter 下能看到一致数值）。
> **Delta / 必要性**：从原始 AVP 用公式重算。

---

## 钩子：一个 0.00，两种误读

数据网站上常常出现一个现象：某件**公认是核心**的装备，Delta 显示 **0.00**。

最典型的例子：重装提莫的鬼索的狂暴之刃 —— **96% 出场率**、reroll 攻速锁定的核心 BIS。打开 DataTFT 看，Delta 一栏显示 **0.00**。

看到这个 0.00，玩家通常陷入**两种解读**：

> **解读 A**：「Δ=0 是核心装的特征 —— 这件装备就是这个阵容本身，with 和 without 没有区别。」
>
> **解读 B**：「按 Delta 的定义 Δ=0 意味着无功无过 —— 那鬼索其实没用？这跟实战经验完全相反，所以数据网站不可信。」

两种解读都来自同一个 0.00，但**两个都是错的**：

- 解读 A 错在**数学**：Δ=0 严格意义就是「带不带都一样」。这是装备无关紧要的特征，不是装备核心的特征。
- 解读 B 错在**数据**：网站显示的这个 0.00 和定义里的 Δ 不一样。按定义自己算，鬼索的 Δ 是 **−0.24**。

也就是说，两个误读**互相强化**：错误的数学解读 + 网站显示和定义不一致的 Δ，看起来正好"自洽"。

本文澄清这两件事，并顺带介绍另一个被严重低估的指标：**必要性 (Necessity)**。

---

# Part 1：Δ 的真正含义 —— 为什么 Δ=0 ≠ 核心装

## Chapter 1: Δ 的定义只有一行

考虑一件具体装备（鬼索的狂暴之刃）。把所有的局分成两堆：

- **w/** ：携带这件装备的局，平均排名记作 `w/`
- **w/o**：没有携带这件装备的局，平均排名记作 `w/o`

Delta 的定义：

```
Δ = w/ − w/o    （负数 = 携带后名次更好 = 好装备）
```

仔细看这个定义。**Δ=0 当且仅当 w/ = w/o**，也就是「带不带这件装备，平均名次完全一样」。

这是「装备没有任何 lift」的特征，**绝不是「装备核心」的特征**。如果一件装备是核心、阵容离不开它，那不带它的局应该显著掉名次（w/o 显著大于 w/），Δ 应该是个明显的负数。

**解读 A 在这里就崩了**：把 Δ=0 当作「核心装的标志」是把数学反着读。直觉上想想 —— 如果鬼索真的「拿和不拿都一样」，96% 玩家凭什么花 BF + Bow + Rod 三件原材料去做？

那为什么不少人会相信解读 A？答案在 Part 2：因为他们看到的数据网站显示，**核心装的 Δ 真的就接近 0**。这才是真正的问题来源。

---

# Part 2：那为什么核心装显示的 Δ 这么接近 0？

## Chapter 2: 自己算一遍鬼索的 Δ

定义清楚了，但显示的 Δ 是 0.00，差距明摆着。让我们手动算一次，看到底哪步对不上。

**w/** 直接读网站的 AVP 列。重装提莫鬼索：

```
w/ = 4.13
```

**w/o** 网站没有直接显示，但**任何数据网站都支持「exclude this item」filter**。在 DataTFT 上：filter 加一条 `exclude 鬼索的狂暴之刃`，再读 AVP：

```
w/o = 4.38
```

代入定义：

```
Δ = w/ − w/o = 4.13 − 4.38 = −0.24
```

**按定义算的 Δ = −0.24**，不是 0。

差 0.24 个名次意味着：没有鬼索的提莫局平均掉到第 4.4 名，有鬼索的稳定第 4.1 名 —— 这才符合「鬼索是核心」的实战直觉。

> 验算：`A = 4.144, freq = 96%`（精确 0.957），由 `A = freq · w/ + (1−freq) · w/o` 反解：`w/o = (4.144 − 0.957·4.13)/0.043 ≈ 4.378`。和手动 filter 读出的 4.38 一致 ✓。

## Chapter 3: 三家网站显示的 Δ 不一样

我们在 DataTFT、MetaTFT、TacticsTools 上同 filter（重装提莫）下观察到的鬼索 Δ：

| 数据源 | 显示的 Δ | 是否吻合公式 `w/ − w/o` |
|---|---:|:---:|
| 自己 exclude filter 后用公式算 | **−0.24** | — (基准) |
| **TacticsTools** | **−0.24** | ✅ 一致 |
| MetaTFT | **−0.09** | ❌ 不一致 |
| DataTFT（某次截图） | **0.00** | ❌ 不一致 |

> 🖼️ 截图位 1：DataTFT 鬼索那行 Δ
> 🖼️ 截图位 2：MetaTFT 鬼索那行 Δ
> 🖼️ 截图位 3：TacticsTools 鬼索那行 Δ + w/o（双重验证）

**有意思的事实**：TacticsTools 的 Δ 列直接吻合公式 —— 而且他们的 w/o 列和 w/ 列代入定义算出来的 Δ 也跟显示列一致。这意味着 **TacticsTools 把 Δ 当作严格的数学定义来呈现**。

MetaTFT 和 DataTFT 的 Δ 列则与公式 Δ 不同，特别是高 freq 装备的 |Δ| 显得更小、更接近 0。具体的算法细节他们没有公开 —— 可能是显示侧的某种 normalization 或稳定化考虑，本文不深究。重点是观察到：**这两家显示的 Δ 不直接等于定义里的 Δ**。

> ⚠️ **DataTFT 的显示值在不同 filter 下还会变**。同一个装备同站换 7 days、换 rank 段，Δ 列给的数能从 0.00 变成别的值。底层 `w/` 和 `w/o` 在任何 filter 下都稳定，所以稳定的「公式 Δ」只能自己算。

## Chapter 4: 实操建议

| 装备 freq | 推荐做法 |
|---|---|
| < 60% | 直接看任何网站的 Δ 列基本可信（差异在该范围内不显著） |
| ≥ 80%（高 freq 核心装） | **看 TacticsTools 的 Δ 列**（直接给公式值），或者在任意网站手动加 "exclude this item" filter，自己代公式 `Δ = w/ − w/o` |

到这里，**第一条线**结束 —— 解读 A 在 Part 1 被拆（Δ=0 ≠ 核心装），解读 B 在 Part 2 被澄清（数据本身没问题，是 DataTFT/MetaTFT 显示的 Δ 和定义不一致；TacticsTools 和手动 filter 都能给公式 Δ）。

但故事还没完。即使你拿到的是公式 Δ —— 鬼索的真 Δ = −0.24 —— Δ 这个指标本身就够好吗？

# Part 3：拿到公式 Δ 之后，它仍然误导你

## Chapter 5: Δ 把低 freq 装备捧到 top

看一下重装提莫数据里**公式 Δ 最负**的几件装备：

| Item | Freq | Δ |
|---|---:|---:|
| Statikk Shiv（神器版） | 2% | **−0.39** |
| Rabadon's Deathcap ★2 | 1% | **−0.40** |
| Rabadon's Deathcap | 30% | **−0.35** |
| Flickerblades（神器） | 3% | **−0.35** |
| Gambler's Blade（神器） | 2% | **−0.31** |
| **Guinsoo's Rageblade（核心）** | **96%** | **−0.24** |

按 Δ 看，提莫的「最强装备」竟然是几个 **2-3% freq 的神器**？而 96% 玩家做的核心鬼索反而排第 6？

**这是 Δ 的另一个问题：低 freq 装备容易受 survivorship 污染**。

仔细想想 —— 能完成 Statikk Shiv 神器的 2% 玩家是什么人？答：carousel 抓到了对应零件、阵容已经稳了 / 经济也够、玩家水平也够，**他们本来就更可能上前 4**。

Δ 把「装备好」和「拿到装备的人本来就强」**完全混在一起**。从公式看，`Δ = (w/ − A) / (1 − freq)`：当 freq 小时分母接近 1，对 (w/ − A) 不放大也不缩小；但因为低 freq 局本身就受 selection 污染，**Δ 把这种 selection 当成「装备贡献」原样呈现**，看起来像 Statikk Shiv 是隐藏神装。

**结果**：如果你按 Δ 排名 prio 装备，会被 carousel 才能凑到的神器、Flickerblades 这些根本拿不到的东西误导，反而把真正的 96% 必出核心鬼索排到后面。

# Part 4：必要性 —— Δ 的 freq 加权，抗 survivorship

## Chapter 6: 必要性的定义

**必要性 (Necessity)** 的定义：

```
必要性 = w/o − A    （正数 = 重要 = 拿掉它整体会变差）
```

也就是「如果没人做这件装备，整体 AVP 会变成什么样」相对当前 baseline 的差距。

代数上，必要性 = `−freq × Δ`，所以它本质是 **Δ 的 freq 加权重排**：

- 低 freq 装备：被 freq 权重压成 ~0（你不会被 Statikk Shiv 神器误导）
- 高 freq 装备：被 freq 权重放大（鬼索的核心地位被正确反映）

按必要性的重装提莫 top：

| Item | Freq | Δ | 必要性 |
|---|---:|---:|---:|
| **Guinsoo's Rageblade** | 96% | −0.24 | **+0.234** ← top |
| Giant Slayer | 62% | −0.21 | +0.131 |
| Rabadon's Deathcap | 30% | −0.35 | +0.104 |
| Hextech Gunblade | 33% | −0.12 | +0.038 |
| Statikk Shiv（神器） | 2% | −0.39 | **+0.009** ← 几乎是 0 |

鬼索回到第一，神器们被压到 ≈ 0。Necessity 的 ranking **跟玩家直觉对得上**。

**对比两个指标在回答的问题**：

| 指标 | 在回答 |
|---|---|
| Δ（公式值） | 「在某一局里，碰巧拿到这件装备能让我提升多少名次？」（per-game lift） |
| 必要性 | 「这件装备对整个阵容生态多重要？少了它整体掉多少？」（comp-level dependence） |

prio 决策（slam 哪件）→ 看必要性。已经决定要堆某件 → 看 Δ 看 per-game lift。

## Chapter 7: 两张等高线图 —— Δ 和必要性的几何形状

把 (出场率, w/) 画成平面，背景填 metric 在该平面上的等值线（A 固定为 4.14），点是上表里的真实装备。

### 必要性 Landscape

![必要性 Landscape](/experiments/2026-05-12-necessity-landscape.png)

观察：
- 等高线在低/中 freq 区域很缓，但接近 freq=1 时**急速向右上拉升** —— 因为 `freq/(1−freq)` 在 freq→1 时趋向无穷。
- 这就是为什么鬼索（freq 96%、w/ 4.13 vs A=4.14，gap 只有 0.01）仍然能排到必要性第一：杠杆系数 `0.96/0.04 = 24×` 把那 0.01 的 gap 放大成 +0.234。
- Rabadon's Deathcap（freq 30%、gap 0.245，是鬼索的 ~24 倍）只有 +0.104 —— 因为权重系数才 `0.30/0.70 ≈ 0.43×`。

### Delta Landscape

![Delta Landscape](/experiments/2026-05-12-delta-landscape.png)

观察：
- 等高线在 freq < 50% 的区域几乎是水平的：Δ ≈ w/ − A。
- 当 freq > 80% 后，等高线急速发散 —— `1/(1−freq)` 在这里也趋向无穷。**高 freq 区域同样的 (w/ − A) 被 Δ 放大、不是缩小**。
- 两张图共用相同的 (freq, w/) 平面，但 metric 几何形状完全不同：必要性在 freq→1 沿 (A − w/) 一侧爆炸，Δ 在 freq→1 沿 (w/ − A) 另一侧爆炸。**两者都不会在 freq→1 时归零**。

> Δ=0 的等高线 **是水平的、不依赖 freq**：当且仅当 `w/ = A` 时 Δ=0。换句话说，「Δ→0」只能由「装备 AVP 等于整体 AVP」引起，**不能由 freq 高引起**。这从图上一眼能看出来 —— 这正是 Part 1 解读 A 错的几何证明。

## Chapter 8: 必要性也不是终极答案

需要承认必要性的几个局限，避免它被神化：

1. **必要性假设 freq 是 lift 的合理代理**。但 freq 高也可能是 selection 的产物 —— 拿到鬼索的 96% 玩家本来就是「够稳的局 + 够熟的玩家」，without 组 4% 是「拿不到的非典型局」。必要性不区分这两种因果。
2. **必要性受 baseline AVP 影响**：同一件装备在不同 condition（filter 紧/松、不同 comp）下绝对值不同，虽然 ranking 通常稳定（参见 [[experiments/2026-04-22-cross-validation-vex-nova95]] Spearman 0.993）。
3. **niche-but-strong 装备会被压制**：低 freq 装备必要性总是低，但不一定是它差，可能只是少有人 prio。本文 Statikk Shiv 神器既可能是 trap、也可能是真有但少人 prio 的隐藏装。
4. **tftable 等工具有更进阶的 debiasing**（IC3 weighting、conditional baseline 等），必要性只是其中较易解释的一步。本文不展开。

实践原则：**必要性适合回答「阵容核心装备」，Δ 适合回答「per-game 边际」，两者结合 + Build Analysis 才是完整答案**。详见 [[methods/build-analysis]]。

## 总结

回到开头那个鬼索 0.00 的双重误读。本文澄清了什么：

| | 误读 A：「Δ=0 是核心装」 | 误读 B：「显示 Δ=0 → 鬼索没用」 |
|---|---|---|
| 错在哪 | 数学：Δ=0 严格意义就是无功无过 | 数据：网站显示的 Δ 和公式 Δ 不一致 |
| 真相 | 核心装的 Δ 应该是显著负数 | 鬼索按公式算的真 Δ = −0.24 |
| 怎么避免 | 理解 Δ 的真正定义；自己代公式 | 看 TacticsTools，或在任意网站手动 exclude filter 自己算 |

更进一步，即便你拿到的是公式 Δ，它对低 freq 装备的「Leverage 放大」会把 carousel 神器捧上天 —— 这就是必要性能解决的事。**必要性 = freq 加权后的 Δ**，把低 freq 神器压到 0、把高 freq 核心放到正确位置，更接近玩家做装备 prio 决策时真正想要的答案。

数据先行，结论后到。下次有人说「这件装备 Δ 接近 0 是因为它必出 / 核心」，请他给一个真 `w/ < A` 但 `(w/ − A)/(1 − freq)` 趋近 0 的真实案例 —— 大概率给不出，因为那种「必出且无 lift」的装备在数据上几乎不存在。看到的 0.00 多半来自该网站的显示算法，不是 TFT 数学的客观属性。
